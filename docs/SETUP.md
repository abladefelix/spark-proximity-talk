# SKANAROUND — Setup

Everything needed to get the app running locally and configured for production.

## 1. Local development

```bash
bun install
bun run dev            # http://localhost:8080
```

`.env` is generated by Lovable Cloud and holds the backend URL and publishable
key. Server-only values (`SUPABASE_SERVICE_ROLE_KEY`, mail/Paystack secrets held
in the database) are never bundled into the browser.

Useful scripts:

| Command | Purpose |
| --- | --- |
| `bun run dev` | dev server with HMR |
| `bun run build` | production build into `dist/` |
| `bun run preview` | serve the production build |
| `bun run lint` | ESLint |
| `bun run format` | Prettier |

## 2. Database migrations

SQL lives in `supabase/migrations/*.sql`, applied in filename (timestamp) order.
Migrations are forward-only: never edit an applied file, always add a new one.

Structure every new table migration in this exact order:

```sql
create table public.thing (...);
grant select, insert, update, delete on public.thing to authenticated;
grant all on public.thing to service_role;
alter table public.thing enable row level security;
create policy "..." on public.thing for select to authenticated using (...);
```

Role checks belong to the `private` schema helpers (`private.is_staff`,
`private.has_role`, `private.is_match_member`, `private.is_pro`) so RLS policies
never recurse and helpers are not callable from the client.

See [DATABASE.md](./DATABASE.md) for the full schema, RPCs and buckets.

## 3. First admin

The first signed-in account can claim ownership:

1. Sign up in the app.
2. Open `/admin` in a browser.
3. If no admin exists yet, the page offers **Claim admin** (`claim_first_admin()`).

After that, further admins/moderators are granted from **Admin → People**.

## 4. Configure the app (Admin console)

Open `/admin` in a desktop browser and work through:

- **App** — app name, logo, accent hue, presence timeout, signal expiry hours,
  daily signal limit, max scan radius, chat TTL days.
- **Mail** — SMTP host, port, TLS, username, password, from name/address,
  reply-to, plus a test send. Required for password resets and Pro receipts.
- **Billing** — enable payments, Paystack public/secret keys, currency, monthly
  and yearly amounts, free-tier caps and Pro feature switches. The **Go Pro**
  tab only appears in the app once billing is enabled with a price set.
- **Backups** — S3 or Google Drive credentials and snapshots.
- **Chat backgrounds / Radar tones** — upload the assets users pick from.

Full details: [ADMIN.md](./ADMIN.md).
